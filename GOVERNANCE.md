# Governance

## Maintainers

The repository owner and maintainers listed in `.github/CODEOWNERS` decide on releases, security fixes and merge policy.

## Decision making

Changes are proposed through issues and pull requests. Technical decisions favor security, correctness, and long-term maintainability over short-term convenience. Significant architectural changes should be documented in `docs/architecture.md` before implementation.

## Release process

Releases are prepared with release-please from Conventional Commits and tagged with a semantic version. Artifact signing and SBOM generation are not configured.

## Becoming a maintainer

Follow the contributor ladder in `CONTRIBUTING.md`. Sustained, high-quality contributions and a demonstrated understanding of the security model are considered for commit access.
